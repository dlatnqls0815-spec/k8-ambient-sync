# 다음 방문 전 확인표

현재는 **추가 방문 일정과 반복 조작을 확정하지 않는다.** 이미 수행한 작업과 확보한 증거를
구분한다. PC 분석부터 진행하고, 현장 소요 시간은 필요한 시험이 정해진 뒤 판단한다.

## 이미 수행한 작업

| 항목 | 완료된 작업 | 현재 부족한 증거 |
|---|---|---|
| 진단 앱 설치 | 원래 v1/v2 및 legacy v1 APK를 각각 전송·설치 시도. 둘 다 동일 인증서 오류로 거부됨 | 구체적인 거부 원인. 직접 GATT 시험은 실행 전 |
| 순정 꺼짐·밝기 | 꺼짐과 최저 밝기 조작. SML 22줄에 raw 1→2 등이 기록됨 | 실제 소등·점등과 raw 값의 대응. raw1=OFF 가설은 육안 대조 전 |
| 순정 테마·직접색 | 드림퍼플과 직접색을 선택하고 원래 설정으로 복원했다고 확인 | 각 선택의 정확한 로그 대응, 복원 때 RGB 요청이 없는 이유 |
| Lotus 전원·최저 | 사용자가 조작 완료를 알림. Galaxy USB 연결 후 보고서도 확보 | 추가 보고서의 ATT 쓰기는 0건. 해당 명령과 실제 발광 반응 대조 |
| Lotus RGB·밝기 | 최초 HCI에서 RGB와 5/10/15/20 조작을 확보·분석 | 이 구간의 반복 수집은 현재 필요 없음 |

수행한 작업은 완료로 유지한다. 추가 보고서의 0건은 조작하지 않았다는 근거로 사용하지 않는다.
원본 위치는 `docs/CLAUDE_HANDOFF.md`의 로컬 자료 목록을 따른다.

## 방문 전에 PC에서 처리할 작업

1. 두 서명 방식의 기존 설치 실패를 분석하고 추가 로그가 필요한 이유를 정리한다.
   로그에 특정 문구가 없다는 사실만으로 제조사 정책을 확정하지 않는다.
2. 기존 SML 및 OEM 분석으로 raw1의 의미와 드림퍼플 복원 경로를 검토한다.
   현재 밝기 변환은 임시다.
3. Claude의 APK 정적 분석에서 확인한 Lotus 전원 프레임 후보를 검증한다.
   정적 코드와 실제 대상 장치의 HCI 대조를 구분한다.
   관련 결과는 `docs/research/PC_ANALYSIS_2026-11-07.md`에 있다.

## 현장 재확인이 꼭 필요해졌을 때만

PC 분석으로 답하지 못한 항목과 수집 목적을 먼저 정하고 필요한 것만 선택한다.

- **설치 오류**는 새 자료가 필요한 경우에만 로그 읽기를 먼저 시작하고 승인 범위에서 재현한다.
- **순정 꺼짐**은 OFF와 1단계의 실제 발광·시각·SML raw 값을 함께 기록해야 할 때만 확인한다.
- **드림퍼플**은 직접색에서 드림퍼플로 돌아가는 경로의 증거가 필요할 때만 기록한다.
- **Lotus 전원·최저**는 연결 전 HCI를 준비한 상태에서 짧게 기록하고 조작 직후 보고서를
  기기에 생성해 보관한다. 실제 반응과 시각을 함께 기록한다.

자료 확보 여부를 확인하고 원래 상태로 복원한다. Galaxy 보고서는 USB ADB 또는
사용 가능한 기존 무선 ADB로 옮긴다. 핫스팟과 USB 연결 제약도 함께 확인한다.
