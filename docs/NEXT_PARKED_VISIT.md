# 다음 방문 전 확인표

현재는 **추가 방문 일정과 반복 조작을 확정하지 않는다.** 이미 수행한 작업과 확보한 증거를
구분한다. PC 분석부터 진행하고, 현장 소요 시간은 필요한 시험이 정해진 뒤 판단한다.

## 이미 수행한 작업

| 항목 | 완료된 작업 | 현재 부족한 증거 |
|---|---|---|
| 진단 앱 설치 | 원래 v1/v2 및 legacy v1 APK를 각각 전송·설치 시도. 둘 다 동일 인증서 오류로 거부됨 | 구체적인 거부 원인. 직접 GATT 시험은 실행 전 |
| 순정 꺼짐·밝기 | 꺼짐과 최저 밝기 조작. SML 22줄에 raw 1→2 등이 기록됨 | 실제 소등·점등과 raw 값의 대응. raw1=OFF 가설은 육안 대조 전 |
| 순정 테마·직접색 | 드림퍼플과 직접색을 선택하고 원래 설정으로 복원했다고 확인 | 각 선택의 정확한 로그 대응, 복원 때 RGB 요청이 없는 이유 |
| Lotus 전원·최저 | 사용자가 조작 완료를 알림. Galaxy USB 연결 후 보고서도 확보 | 추가 보고서의 ATT 쓰기는 0건. 해당 명령과 실제 발광 반응 대조 |
| Lotus RGB·밝기 | 최초 HCI에서 RGB와 5/10/15/20 조작을 확보·분석 | 이 구간의 반복 수집은 현재 필요 없음 |

수행한 작업은 완료로 유지한다. 추가 보고서의 0건은 조작하지 않았다는 근거로 사용하지 않는다.
원본 위치는 `docs/CLAUDE_HANDOFF.md`의 로컬 자료 목록을 따른다.

## PC 분석 결과 (2026-11-07 완료)

PC에서 할 수 있는 분석은 끝났다. 근거는 [PC 재분석 5장](research/PC_ANALYSIS_2026-11-07.md)에 있다.

- 순정 꺼짐은 `raw1=OFF`를 작업 기준으로 삼는다. 남은 것은 실제 소등 육안 확인뿐이다.
- 드림퍼플 복원도 `setSMLRGB` 경로다. **테마 재선택 기록은 더 필요 없다.**
- 설치 실패 원인과 Lotus 전원 프레임은 PC 자료로 더 좁힐 수 없다. 현장 자료가 필요하다.

## 최종 현장 확인표 (정차, 한 번에)

준비: 노트북·Galaxy USB 케이블. 차량과 노트북을 같은 핫스팟에 연결한다. 휴대폰 HCI 스누프 로그가 켜져 있는지 확인한다.
SmartThings 같은 BLE 앱 조작과 휴대폰 재부팅·Bluetooth 끄기는 4번이 끝날 때까지 하지 않는다.

| 순서 | 할 일 | 남길 기록 | 확정되는 것 |
|---|---|---|---|
| 1 | 무선 ADB 연결 후 `tools/watch_k8_sml_adb.py` 감시 시작 | SML 로그 | 2의 raw 값 |
| 2 | 순정 앰비언트 **꺼짐 → 1단계 → 꺼짐** | 각 조작 시 실제 소등/점등 여부와 시각 | raw1=OFF 확정, 임시 함수 제거 |
| 3 | 진단 APK 설치 **1회**, 바로 PackageManager 로그 저장(5-5, 1장 명령) | install-logcat.txt | 설치 거부 원인 |
| 3-1 | (선택, 별도 승인) `services.jar`/`services.odex` 읽기 전용 pull | private 사본 | `-104` 설정 위치 정적 확인 |
| 4 | Lotus 앱에서 **전원 끄기 → 켜기**, 바로 그 자리에서 Galaxy 버그 보고서 생성 | 보고서 ZIP, 조명 반응·시각 | 정적 전원 프레임과 HCI 대조 |
| 5 | 원래 설정(드림퍼플·평소 밝기)으로 복원 | — | — |

이미 확보한 RGB, 5/10/15/20%, 테마 선택 조작은 반복하지 않는다.
3에서 설치가 다시 거부되면 재서명은 시도하지 않는다. 설치가 성공하면 사용자 승인 범위에서 GATT 탐색 1회를 진행한다.
