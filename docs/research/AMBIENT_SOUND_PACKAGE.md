원본은 이 저장소에 넣지 않는다. 라이선스 표기를 찾지 못해 코드·팔레트를 복사하지 않고 사실만 적는다.

## 대상과 설치 방식 — K8에는 설치하지 않는다

- README는 특정 펌웨어 지문(`wp_daudioplus…us`, 20260507)과 에뮬레이터만 대상으로 한다. K8 GL3HEV.KOR 260902는 대상이 아니다.
- 일반 `pm install`이 거부돼서 root 훅이 APK를 **`/system/app`에 직접 복사**한다. 런처 타일 설정도 바꾼다.
  우리 규칙(시스템 파티션 변경 금지)과 맞지 않는다. 우리 진단 앱은 NEMESIS `kind=apk` 경로를 쓴다([설치 문서](GEN5W_INSTALL_ALLOWLIST.md)).

## K8 분석에 바로 쓰이는 사실

| 항목 | 패키지 소스 | K8 증거와의 관계 |
|---|---|---|
| Binder 서비스 | `com.hkmc.micom.system`, 인터페이스 `com.hkmc.micom.ISystemService` | K8 `automotive` DEX와 같은 인터페이스 |
| 밝기 호출 | transaction **77**, `(5, level+1)` | K8 `TRANSACTION_setSMLConfiguration = 0x4d(77)`. **코드 번호까지 같다** |
| 색상 호출 | transaction **78**, 채널마다 `[0x00, 값]` 2바이트 | K8 `TRANSACTION_setSMLRGB = 0x4e(78)`. 상태 요청은 K8 `0x4c(76)` |
| 직접색 인코딩 | 상위 바이트 **0x00** + 하위 바이트 0~255 | K8 직접색(상위 0x00) 가설과 일치. 하위 바이트가 곧 RGB 값이다 |
| 밝기 의미 | 메뉴 단계 0~10을 `level+1`로 보냄. "brightness 1 = dimmest on"(단계 1 = raw 2), 종료 시 단계 1로 둠 | **raw1 = 단계 0 = 꺼짐, raw2 = 가장 어두운 점등.** 우리 `raw1=OFF` 판단과 같다 |
| 색상 팔레트 | 순정 직접색 64색 표(Ioniq 5/Grandeur 계열) | K8 관측 직접색 #FA0451·#84E562·#1020EF·#9B21EF는 이 표에 없다. **차종별 팔레트가 다르다** |
| 실행 방식 | NEMESIS 서비스가 DEX를 `app_process`로 UID 1000에서 실행 | APK 설치 없이 시스템 UID 코드를 돌리는 선례. BLE에는 아직 쓰지 않는다 |

## 사용자 화면(밴드 색상표)에 대해

사용자가 보낸 12밴드 표(서브베이스 빨강 → 심벌 분홍)는 이 앱의 **소리 반응 레시피**다. 주파수 밴드마다 팔레트 색과
증폭 배수를 정한 것이다. 순정 테마·직접색의 실제 색 대응 근거는 아니다. 다만 순정 직접색이 하위 바이트 RGB 그대로라는
위 사실 덕분에 **K8 직접색은 Lotus RGB로 그대로 옮길 수 있다**(사용자 비교: #9B21EF ≈ Lotus 126,0,255, 색상각 차이 약 6°는 무시 가능).

## 정리

- `raw1=OFF`는 K8 수집 2건 + EV6 상류 규칙 + 이 패키지의 실차 기반 주석까지 세 갈래 근거가 생겼다.
  현장 소등 확인은 남기되 우선순위를 낮춘다.
- 직접색(상위 0x00)은 하위 바이트를 RGB로 쓰는 변환을 채택할 근거가 생겼다. 테마(상위 0x01)는 계속 별도 표가 필요하다.
